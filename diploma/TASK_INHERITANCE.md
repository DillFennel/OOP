# Одиночное наследование на примере канала сообщений

В примере отправитель (Producer) передает сообщения получателю (Consumer) через канал. 
Был реализован базовый класс Channel, в нем заданы общие для всех видов канала операции. Отправителю доступен метод Publish(), чтобы поставить сообщение в очередь. Получателю же доступен метод TryPop(), который позволяет взять очередное сообщение, и метод Commit(), который позволяет подтвердить обработку сообщения.

Есть два наследника Channel: SimpleChannel и NewChannel, причем наследование одиночное, так как у каждого из дочерних классов один непосредственный родитель. Оба наследуют счетчик опубликованных сообщений, а способ хранения и момент удаления сообщения каждый определяет сам.

Предположим, отправитель положил в пустую очередь одно сообщение.

| Действие получателя | SimpleChannel | NewChannel |
|---|---|---|
| Получил сообщение через TryPop() | Сообщение удалено, очередь пуста. | Сообщение остается первым в очереди и ждет подтверждения. |
| Обработал сообщение и вызвал Commit() | Очередь уже пуста. | Канал удаляет подтвержденное сообщение. Теперь очередь пуста. |

Получатель обрабатывает сообщения по одному. Он подтверждает текущее сообщение и только потом запрашивает следующее. Если вызвать TryPop() у NewChannel еще раз до подтверждения, канал снова выдаст то же сообщение.

Так моделируется переход на другой способ передачи сообщений в предметной области моей ВКР. В main.cpp по умолчанию выбирается SimpleChannel, если указать флаг --new_channel, то выберется NewChannel. Отправитель и получатель в обоих случаях работают с родительским классом Channel. Если понадобится третий способ передачи, его можно реализовать еще одним наследником и выбрать в main.cpp.
